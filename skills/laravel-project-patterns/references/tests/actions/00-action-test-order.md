# Action Tests: Ordered Contract Checklist

Action integration tests invoke the real operation and check persistence, guards, ordering and side effects. Select examples matching the inspected inputs and dependencies; controller delegation, model constraints and resource serialization stay in their own categories.

Inspect the action, input class, factories, constraints and test bootstrap. Use its database isolation and freeze time for exact timestamps. Keep standalone `it()` where the suite has no `describe`, canonical names and example case order. Separate setup, operation and assertions with blank lines; related fixture declarations may stay consecutive.

Keep full field vectors and dataset rows. Omission and explicit `null` differ; soft deletion and physical removal differ. Assert unchanged state after rejection where shown. Mock only the stated collaborator: job/notification fakes prove dispatch, query observers prove SQL shape, and synchronous conflict stubs prove recovery, not concurrency.

Use `recycle()` for existing default parents; retain explicit `for()` for optional roles, trashed parents or deliberate mismatches. Inspect derived foreign keys before simplifying fixtures. Synthetic class names, messages and constraints illustrate contracts, not requirements to add.
